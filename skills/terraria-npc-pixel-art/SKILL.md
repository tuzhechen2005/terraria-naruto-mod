# Terraria NPC 像素美术

目标是让最终游戏尺寸下的人物好看、可辨认。直接生成像素角色，尽早导出真实小图；大图、放大截图和色数指标不能代替最终尺寸的外观。

## 先看已经被认可的成品

使用前查看 `assets/approved-iruka-right.png`（真正的 64×80 游戏尺寸单帧）与 `assets/approved-iruka-6x.png`（同一帧整数放大）。用户于 2026-10-05 对这个**无嘴线、眼睛竖向两格**版本明确评价「现在的这个就是完美」，要求其他 NPC 复用。这是本 skill 的参考版本，不要退回旧伊鲁卡或昨晚已被否决的全员高清版本。

- 人物实际高 62 像素，最终显示比例为 1，脚底最后一行 y=75。宽高与基线是该模组城镇 NPC 的起点，可按角色体型和已有代码调整。
- 保留较大、饱满的像素色块、暖色明暗和清楚剪影。允许眼睛等关键特征使用较细纹理像素；成品并非全图严格 2×2 网格。
- 普通裸露脸默认省略嘴线，优先给眼睛留空间。**眼睛大小、宽高比、眼型和露出程度按每个人单独设计，不设统一格数、统一像素高度或统一眼白/瞳孔模板。** 范例的可见眼睛高 4 个屏幕像素只是伊鲁卡这张定稿的选择，不是其他角色的默认值或最低值。用户明确补充「每个人的眼睛大小都不一样的」。
- 其他角色保留各自的头发、面罩、眼镜、斗笠、体型和衣装。伊鲁卡的鼻梁疤与马尾是他的特征，不应复制给其他 NPC。被遮住的眼睛不要强行画出来。

## 制作方式

1. 读取项目当前规则、相关 NPC 代码和已有贴图，确认纹理画布、帧数、`NPC.scale`、朝向与脚底。只处理用户指定的角色与动作。
2. 用可用的内置图像生成工具直接生成**粗像素风的整个人物**，把已认可伊鲁卡放大帧作为画风参考，角色原作参考单独标明身份用途。工具在当前会话可用时遵循 imagegen 技能；不要改走需要 API 密钥的方式，也不要以脚本从零拼出人物代替生成。
3. 首轮先做一张站立图。减少衣服细纹和小口袋，把空间留给脸和剪影。提示词写低分辨率设计目标，但不要声称模型已经输出了精确网格。模型常会输出大图、半透明晕边和不规则像素块。
4. 通过确定性导出把候选变成真正的小 PNG，之后所有审美检查看这张 PNG。优先按目标屏幕高度直接导出、1 倍显示，避免先缩到 23 格又放大 1.36 倍。也不要为了强制统一网格把眼睛采样成一条白柱。按角色参考保持各自的眼型：小眼、细长眼、圆眼、闭眼或遮眼都可能成立，不能因为伊鲁卡大眼被认可就给其他人放大眼睛。
5. 若眼白、疤、面罩边界丢失，先检查采样相位，再做局部图像编辑。去嘴、加高眼睛等修改只作用于相应区域；保留已认可的身体、色彩和剪影。生图模型改变其他部位时，只合成确认过的局部结果，并记录矩形和检查局部以外未变化。不能把伊鲁卡的脸部坐标用于其他角色。
6. 展示最终 PNG 的正常尺寸、3 倍对比和必要的 6 倍局部，使用明暗两种背景，与现有 NPC 并排。正常尺寸是决定结果的依据。用户已认可的外观要保留，不因色数多或不够像达兹纳而重画。

生成与局部编辑提示词、导出参数、伊鲁卡案例的依据见 [references/workflow.md](references/workflow.md)。导出时使用 [scripts/export_sprite.cjs](scripts/export_sprite.cjs)，它只做裁切、采样、透明硬化、对齐、镜像和检查，不创造或修画五官。

## 动画与接入

- 本 skill 的调用不是批量替换、动画制作或游戏接入的额外授权。按当前用户请求完成；若仅要样张，就交付样张。用户认可底稿后，按其已授权的范围继续动作。
- 动画沿用同一底稿的脸型、体型、颜色、眼型与无嘴线设计。各帧用共同的导出比例，不要把每帧按各自包围盒强行拉成相同身高。站立、走路、坐下、攻击要像同一个人。
- 动作生图后，在真实小帧中逐帧对照**该角色自己已认可的面部**，检查眉、瞳孔、护额阴影是否合成大黑块或挤掉眼白。出现漂移时优先局部恢复该角色底稿的眉眼，保留已通过的身体动作；不能仅凭头发与服装相同就宣称面部一致。
- 对齐与游戏实际脚底锚点一致，检查朝向、走路循环、姿势变化和头像。不要重复站立帧冒充完整动作。
- 扩展或修复走路时，检查肩颈、马甲下摆/裤腰、骨盆与大腿根在同一姿势中的接续和循环变化。局部复用须先按身体锚点匹配；不要把邻帧整截躯干覆盖到另一组腿上。alpha 连通不等于身体结构合理，须看真实小图与首尾循环，避免上身与腿各自在动。
- 连续动画必须检查头、胸口、腰髋的共同锚点和材质色块，不能只对齐脚底或腰轴。两批独立生图各取半循环容易造成头形、眼高、马甲宽度及色彩跳变；优先从同一底稿扩展整套动作，必要时按匹配的肩颈锚点复用已认可头部。普通慢走可保持头部固定；起伏须是有序运动。先看循环与叠帧再判定通过，GIF使用全循环公用色板，并用无损APNG或PNG帧排除编码色漂。
- 接入时修改的是游戏真正消费的贴图及相应尺寸/缩放代码。伊鲁卡与卡卡西已于 2026-10-05 以完整动作表接入、1 倍显示；其他角色仍需检查实际代码。直接把 62 像素新帧套上旧 `ScaleFor(46)` 会变大；不要把 skill 附带的单帧当作完整贴图表。
- 完成授权的接入后运行项目相关验证；构建与无头加载不等于实机美术验收。

## 交付与判断

保留生成原图、最终帧、真实尺寸对比、提示词、导出参数以及已检查/未检查项。在本仓库按 `art/AGENT_HANDOFF.md` 的请求/交付流程工作；当前会话直接生图与后台桥接只能选一个，避免重复任务。

最低机械检查包括实际画布与身高、脚底、0/255 alpha、透明像素零 RGB、朝向、无裁切；局部编辑还应检查范围以外像素不变。数量指标只作诊断，不设全角色统一的色数上限或脸部尺寸。

成品是否成立取决于正常尺寸下的轮廓、眼睛与角色特征，而不是把所有眉、鼻、嘴塞进去。不确定时展示真实小图并具体指出缺陷；不得把用户对大图的认可写成对小帧或游戏内效果的认可。
