# Mac 游戏模式：暂停后台应用

双击项目根目录的 `游戏模式.command`（或 `bin/泰拉瑞亚游戏模式.app`）。在窗口中勾选 Chrome、Codex、Visual Studio Code / Claude。默认只勾选 Chrome；选择会记住。窗口打开时不会暂停任何程序。

- **暂停后台并启动游戏**：暂停所选应用，已有 tModLoader 时接管，否则通过 Steam 启动游戏。
- **仅暂停后台（不启动游戏）**：适合已经进入游戏后使用；不请求启动 Steam 或游戏，也不要求安装 Steam。已有游戏时接管，完全退出后自动恢复。没有游戏时保持暂停，点击“恢复运行”结束；之后检测到游戏时也会自动接管。这条入口没有启动超时。
- **恢复运行**：继续运行原进程，结束游戏模式，游戏本身继续运行。

## 自动英文输入法

“进入游戏时自动切换英文输入法”默认开启。**保持工具运行并勾选该选项，切入 tModLoader 就会自动切英文，不必点击暂停后台。** 也适用于两个暂停入口。启动暂停会话时仍会记录原输入法并切英文。

切入游戏后在约 0.25、0.8、1.5 秒复查当前输入法，处理系统/游戏稍后恢复中文的情况；切出游戏、取消选项或进入新一次游戏焦点时，旧检查失效。稳态游玩不持续强制英文，切入约 1.5 秒后可手动换中文聊天；下次切回游戏再应用英文。除了前台通知，轻量焦点轮询还覆盖 SDL 未发送通知的情况；初次发现新客户端可能需要约 3 秒。

优先选择系统已经启用的 ABC，其次美国键盘，再选其他英文键盘布局。不会添加输入法、改变快捷键或安装常驻服务；没有可用英文键盘时会提示，取消该勾选可继续使用暂停功能。

结束暂停会话时尝试恢复进入会话前的输入法。如果当前输入法已经被你手动换成其他输入法，则保留你的选择。输入法恢复失败不会阻止后台应用恢复；记录保留供重试。

自动英文与暂停会话独立：结束暂停后，只要工具仍运行并勾选选项，再次切回游戏仍会应用英文。取消选项或退出工具停止自动切换。独立英文功能不创建暂停恢复记录，也不修改其他应用的输入法设置；系统仍自行管理各窗口记住的输入法。

工具保留进程、窗口、标签页，用 `SIGSTOP` 暂停选中应用及其同用户子进程，根据所选入口启动或接管 tModLoader。完全退出游戏后约 12–15 秒，用 `SIGCONT` 恢复原进程，不退出、不重开应用。也可以随时点“恢复运行”；这不会关闭游戏。游戏已运行时也可开启此工具。

## 能做到什么

- 暂停应用的 CPU 活动，阻止暂停的进程继续执行和分配内存。
- **不会立即释放已经占用的 RAM，也不保证帧率改善。** 已有内存是否被压缩、换出由 macOS 决定。内存不足导致的卡顿仍需实机比较。
- 暂停期间窗口无法操作，下载、音视频、联网请求、AI 任务可能超时。先等 Codex / Claude 当前任务完成；恢复执行不保证恢复已经断开的网络连接。
- 只处理窗口中明确选择的三个应用，不按“占用高低”自动暂停其他软件。Steam、游戏、此工具与恢复保护进程保持运行；若从某个终端直接启动工具，其祖先进程也会被保护。

Apple 的[原生游戏模式](https://support.apple.com/zh-cn/105118)侧重 CPU/GPU 优先级和减少后台任务占用。此 Mac 满足 Apple silicon / macOS 14+ 条件，但 tModLoader 是否支持 macOS 原生全屏并被系统识别，需要游戏运行时确认；游戏自己的全屏设置不等于系统原生全屏。

## 恢复保护

- 每个暂停请求前原子保存 PID、启动时间、可执行文件和用户 ID。恢复时再次核对，避免 PID 被复用后误操作其他进程。
- 选择启动入口时，超过 3 分钟仍未检测到客户端，恢复后台。扫描失败不当作游戏退出；排除服务器、构建进程与 `-terrariasteamclient` 辅助进程，处理游戏进程短暂重启。
- 窗口关闭按钮在游戏模式期间只最小化；退出工具会先恢复后台。
- 独立恢复保护进程在窗口进程异常退出后尝试恢复。二者都被结束时，重新打开工具，点击“恢复运行”。恢复失败保留记录以便重试。
- 原本已暂停的进程不归本次工具管理，不恢复它们。停止/恢复期间发生的外部进程状态变化仍存在竞态；不要与其他暂停工具同时操作同一应用。
- 状态保存在 `~/Library/Application Support/TerrutoGameMode/`，不提交进 Git；无登录项、常驻服务、管理员权限、内存清理或系统优先级修改。旧版本恢复记录仍可读取；新记录额外保存原输入法与英文键盘标识。

## 开发与验证

```sh
./scripts/build-game-mode.sh
./scripts/test-game-mode.sh
'tools/GameMode/bin/泰拉瑞亚游戏模式.app/Contents/MacOS/GameMode' --diagnose
```

需要 macOS 和系统 Swift 编译器（Command Line Tools）。生成的 `.app` 与测试程序位于忽略的 `bin/`，源码位于本目录。只读 `--diagnose` 显示客户端、前台应用 PID、游戏激活状态与当前/可用英文输入法，不暂停、恢复、启动任何应用，也不写入状态。

73 项检查覆盖目标进程与子进程选择、预先暂停/其他用户/工具祖先排除、客户端检测、两种入口与后续游戏接管、启动超时与退出宽限、恢复记录、PID 身份验证；模拟输入法覆盖英文布局选择、原输入法恢复、保留手动选择、失败重试、旧记录兼容及输入法失败不影响应用恢复。新增回归检查覆盖“游戏外英文、切进游戏稍后变中文”的修正、早期轮询不吞掉延迟检查、快速切出/切回取消旧检查、选项关闭、延迟回调过期与稳定游玩允许中文聊天。

使用测试程序自己的心跳进程验证实际暂停/恢复，以及所有者退出后的恢复保护。2026-10-04 原生窗口验证：取消三个应用勾选后执行“仅暂停后台”，没有启动游戏；真实输入法由中文拼音 `com.apple.inputmethod.SCIM.ITABC` 切至美国键盘 `com.apple.keylayout.US`，恢复后回到原拼音，恢复记录清除，最后恢复用户原有三个勾选。该轮没有暂停实际 Chrome/Codex/VS Code。Steam 游戏启动、游戏退出自动恢复与 FPS 对比仍需实机验收；此前实际应用暂停与内存采样见 `docs/reviews/2026-10-04_游戏启动前后内存实测.md`。

2026-10-05 修复版已构建并在原生窗口打开，未暂停后台；上述时序回归通过模拟服务验证。现有 tModLoader 运行中，但采样期间未成为前台，修复后游戏内的自动英文效果尚待用户确认。
